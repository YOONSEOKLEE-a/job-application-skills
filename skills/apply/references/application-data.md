# 입력 사실과 누락 점검

개인 사실은 현재 사용자의 원본 자료에서 읽는다. 이 문서는 입력·검증 방법만 정의하며 특정 지원자의 값이나 경험을 포함하지 않는다.

## 사실의 출처와 변경

- 사용자 지정 자료 폴더에서 프로필, 기업별 최신 초안, 증빙, 업로드 파일 매핑, 최근 입력·수정 기록을 찾는다.
- 최신 사용자 정정, 공식 증빙, 현행 원서의 항목 정의를 대조한다. 과거 초안이나 에이전트 결론을 검증된 사실로 승격하지 않는다.
- 증빙이 충돌하면 출처와 정정 시점을 구분한다. 학위·자격·논문 저자 등은 원본으로 확인하고 미해결 사실만 묻는다.
- 원본 변경은 현재 사용자의 허용 범위에서만 한다. 확인된 변경의 출처·일자를 개인 작업 공간에 기록하고 관련 입력본에 반영한다.
- 활동기간과 수상일, 교육기간과 수료증 발급일, 출입국과 학기·프로젝트 기간을 구분한다. 파일 수정일을 연구 시작일로 쓰지 않는다.
- 월 단위 항목에 임의의 일자를 만들지 않는다. 정확한 일자가 필수이면 근거를 찾거나 확인한다.
- 추출하지 못한 문서는 동명 PDF 등 확인 가능한 대체본을 찾아 실제 대조 범위를 기록한다. 읽지 못한 원본까지 검증했다고 하지 않는다.

## 전체 항목 점검표

| 항목 | 확인할 내용 |
|---|---|
| 지원정보 | 회사·사업부·직무·지망·근무지·마감·중복지원 규정, 현재 모집 목록 |
| 기본정보·사진 | 현재 사용자 확인값과 선택한 사진, 불러온 정보의 누락 |
| 학력 | 캠퍼스·주야간·전공 분류·졸업예정일, 회사별 선택값 |
| 성적 | 전체/전공 이수학점과 GPA 분모, P·0학점 처리, 기업별 제외 기준 |
| 경력 | 공식 직함, 실제 근무지, 담당업무, 재직/퇴사 상태와 종료일 |
| 해외 경험 | 활동 종류, 전체 기간, 국가·기관·설명 |
| 연구·논문 | 각 논문의 기여·저자·채택/발표/출판 상태, 해당 입력란의 학위 조건 |
| 수상 | 개인/팀 구분, 수상일·기관·훈격, 활동기간과의 차이 |
| 교육 | 실제 교육기간·시간·수료 상태, 발급일과의 차이 |
| 장학·활동 | 선발기관·선발일·지원기간·활동 내용 |
| 어학·자격 | 성적표 날짜·등급·번호·유효기간, 공식 연동 여부 |
| 병역·지원대상 | 확인된 분류, 회사의 항목 정의 |
| 자소서·추가질문 | 현재 원문과 모든 하위 질문, 글자/byte 제한·블라인드 규정 |
| 파일·동의·제출 | 올바른 파일 내용·업로드 완료·허용된 동의/제출·서버 반영 |

선택항목도 원본의 적용 가능한 이력을 적합한 칸에 반영한다. 자소서에 언급했다는 이유로 별도 이력란을 생략하지 않는다. 비해당·금지·입력란 없음은 이유를 남기고, 사용자가 특정란만 수정하도록 요청하면 그 범위를 따른다.

## 성적·학력

- 회사별 산정 지침과 현재 성적표로 계산한다. 한 회사의 전공기초 제외값을 다른 회사에 복사하지 않는다.
- P 과목의 취득학점과 GPA 분모를 구분하고 전체 과목 목록과 개별 학점을 대조한다.
- 증명서와 위젯의 분류가 다르면 임의 대응하지 않는다. 졸업일, 입사 가능일, 공학교육 인증 여부도 각각 확인한다.
- 인재 Pool의 오래된 졸업연도·전공분류·사진이 새 원서로 정확히 옮겨졌는지 확인한다.

## 해외·수상·교육·연구

- 해외 체류 전체 기간을 개별 수업·연구 기간으로 축소하지 않는다. 상충하는 날짜는 원본·사용자 정정·사이트 요구 증빙을 대조한다.
- 수상일은 활동기간과 다르고, 교육 수료는 수상이나 국가자격 취득과 다르다. 팀 수상을 개인 단독 수상으로 쓰지 않는다.
- 학위 전용 논문란에 연구를 넣기 위해 보유하지 않은 학위를 선택하지 않는다. 적합한 다른 이력란을 찾는다.
- 논문별 본인의 역할을 구분한다. 채택을 발표·출판 완료로, 제1저자를 단독저자로 확대하지 않는다.

## 자소서와 경험 선택

- 현재 사용자의 직무 목표와 경험 우선순위를 따른다. 한 회사의 선호·제외 조건을 다른 사람에게 적용하지 않는다.
- 문항별 핵심 사건을 분배하고 같은 사건의 일부를 별개 프로젝트로 포장하지 않는다.
- 코드·연구·프로젝트의 기술 설명은 현재 원본으로 확인한다. 사용자가 폐기·정정한 서사를 옛 초안에서 되살리지 않는다.
- 지원 업무를 전체 책임으로 확대하지 않는다. 깨달음과 이후 실제 개선 행동·성과를 구분하고 미확인 성과를 발명하지 않는다.
- 취미·제품 사용·감정·지원 동기도 사용자 근거가 필요하다. 포괄적인 작성 요청을 경험 발명 허락으로 해석하지 않는다.
- 현재 회사의 블라인드 규정과 실제 모집직무·문항을 우선 확인한다. 과거 문항과 미확인 예비 초안을 현재 답변으로 확정하지 않는다.
- 공백·줄바꿈 포함 글자 수와 사이트 byte 계산을 확인한다. 레거시 byte 제한을 UTF-8 byte만으로 단정하지 않는다.

## 불러오기와 수정

- 인재 Pool 신규 등록·보관 동의는 별도 사용자 의도를 확인한다. 한 회사 로그인 승인을 다른 회사 가입 승인으로 확대하지 않는다.
- 불러온 회사별 선택값, 사진, 날짜, 성적, 이력 행수, 실제 자소서 문항을 다시 검증한다.
- 수정 가능한 화면이 열리면 실제 값 수정 → 저장 → 필요한 재제출 → 필드·제출상태 확인 순으로 진행한다.
- 원본 정정, 사이트 저장, 사이트 최종제출을 서로 다른 상태로 기록한다. 사용자가 직접 제출했으면 중복 제출하지 않는다.
