# 로그인 및 효율적인 브라우저 제어

## 계정 정보와 작업 범위

- 현재 사용자가 요청한 사이트와 공식 호스트를 먼저 확인한다. 다른 사용자의 계정, 과거 로그인 성공 기록, 비밀번호 후보를 기본값으로 가져오지 않는다.
- 기존 브라우저 로그인 세션을 우선 활용한다. 새 로그인이 필요하면 현재 사용자가 승인한 비밀관리 도구 또는 직접 입력을 사용한다. 이 공유 패키지는 자격증명 조회 스크립트나 저장소를 포함하지 않는다.
- 비밀번호·인증코드·쿠키·세션 토큰을 채팅, 스킬, 파일, 로그, Git에 복사하지 않는다. 도구가 안전한 전달을 지원하지 않으면 필요한 입력 단계만 사용자에게 맡긴다.
- 로그인만 요청받으면 계정 생성, SNS 연결, 암호 변경, 지원서 제출로 범위를 넓히지 않는다. 기존 승인은 해당 사용자·사이트·행위 범위에서만 적용한다.

## 제어 방식 선택

- 현재 제공된 브라우저 도구 문서를 읽고 지원되는 API만 사용한다. 짧은 로그인은 접근성 요소 기반 입력·클릭으로 처리하고 반복 입력은 지원되는 locator로 묶는다.
- 사용자가 지정한 브라우저와 현재 탭을 확인한다. Chrome과 다른 브라우저의 로그인이 공유된다고 가정하지 않는다.
- 현재 DOM에서 관측한 레이블·역할·placeholder를 사용한다. 오래된 탭/노드 ID나 화면 좌표를 하드코딩하지 않는다. 구조나 오류가 달라지면 새 상태를 읽는다.
- DOM/접근성으로 원인을 구분할 수 없을 때 현재 스크린샷을 확인한다. 별도 OAuth 창, 리다이렉트, 모달을 원래 탭의 무반응으로 오진하지 않는다.
- 헤드리스·CDP 전환은 인증이나 CAPTCHA의 해결책이 아니다. 현재 도구가 공식 제공하는 연결만 사용하고 디버깅 포트 개방·보안 해제·프로필 복제로 우회하지 않는다.
- 로그인 실패 뒤 오류와 추가 인증 상태를 읽는다. 비밀번호를 추측하거나 변형하지 않는다. 잠금·횟수 제한·추가 본인인증이 나타나면 반복 시도를 멈추고 필요한 단계만 요청한다.
- 현재 범위에서 승인된 일반 로그인과 통상 확인창은 계속 처리한다. 도구의 추가 확인 요구가 있으면 해당 단계만 따른다.
- 로그인 성공은 인증된 마이페이지·로그아웃 표시 등 명시적 상태로 확인한다. 성공 후 비밀번호를 더 시험하지 않고 탭을 유지한다. 반복 로그인이나 무인 제출은 별도 요청 없이 만들지 않는다.

확인창·파일 업로드 등 개별 장애는 [브라우저 복구 절차](browser-recovery.md)를 따른다.
